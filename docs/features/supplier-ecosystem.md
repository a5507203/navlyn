# 供应商生态页面

## Concept Brief

### 当前阶段判断

现有“客户与合作”页面从单一介绍页和占位子页扩展为可检索的供应商生态与详情入口，属于用户可感知的新功能和信息架构调整。

### 目标用户

- 潜在客户与采购人员：按供应商或产品快速定位公开资料。
- 合作伙伴与渠道人员：了解 Navlyn 生态成员及其产品范围。
- 项目咨询访客：直接进入供应商目录，查找合作伙伴和公开产品资料。

页面公开访问，不区分登录角色或权限。

### 核心问题

现有 `/partners` 只有品牌介绍与联系按钮，`/partners/alliances` 和 `/partners/distributors` 仍是占位页面。访客无法搜索真实供应商、查看产品资料或下载对应 PDF。

### 核心概念定义

- **客户与合作入口**：全站导航中的供应商目录入口；直接进入规范地址 `/partners`，不再包含二级菜单。
- **供应商生态**：公开展示供应商 Logo、简介、资料状态及可检索产品的目录；不是供应商管理后台或采购平台。
- **资料已就绪供应商**：具备 Logo、简介、至少一个公开产品和 PDF 资料，可进入详情页。
- **资料准备中供应商**：可在目录中展示，但不可进入空详情页。
- **供应商详情页**：展示供应商简介、产品图片、产品说明和 PDF 下载；不是电商交易页。
- **实时搜索**：在本地静态数据中按供应商名称、别名、产品名称和关键词即时筛选，不调用远程 API。

### MVP 边界

1. 桌面端和移动端“客户与合作”均为单一链接，直接进入 `/partners`，不显示箭头、下拉菜单或“联系我们”子入口。
2. `/partners` 为供应商生态规范地址；旧 `/partners/suppliers` 使用 replace 重定向至 `/partners`；详情继续使用 `/partners/suppliers/:supplierSlug`。
3. `/partners/alliances`、`/partners/distributors` 与现有 `/contact` 页面继续保留。
4. 供应商生态使用用户提供的地球夜景图；首屏文字固定为“链接世界，航向未来”与“每一处航迹，都有我们的伙伴。”，英文显示对应翻译。
5. 桌面端每行 4 张卡片，间距保持在 24–32px；平板 2 列，手机 1 列。
6. YellowScan、云洲智能、火莹科技、禾启智能可进入详情；其余显示“资料准备中”且不可点击。
7. 详情页按 Word 要求只展示图片/渲染图、产品说明与 PDF 下载，不展示视频。
8. 站点语言入口只保留中文、英文；旧的法文、西班牙文持久化值回退为中文。

### 非目标

- 不删除或重定向现有全球合作伙伴、国际经销商页面。
- 不修改现有联系表单业务。
- 不删除页脚或悬浮的联系入口。
- 不实现购物车、价格、下单、询价状态、登录、供应商入驻或 CMS。
- 不展示素材中的视频。
- 不从 PDF 推导或编造产品规格、合作关系、客户案例。

### 关键假设

- `/partners` 作为供应商生态唯一规范列表地址；旧列表地址只用于兼容已有链接。
- 详情继续使用稳定的英文 slug 与现有 `/partners/suppliers/:supplierSlug` 地址。
- 旧 `/partners/suppliers` 兼容入口由官网维护者负责；接入访问日志后连续 90 天无访问即可移除，最晚在下一次 partners 信息架构调整时复审。
- `Yelloscan` 统一为官方写法 `YellowScan`。
- 素材目录中的“火莹科技”作为页面正式名称；Logo 文件名中的“火萤”视为素材命名差异。
- 缺少正式简介时使用不包含性能、资质或合作承诺的保守占位文案，后续可由内容方替换。

### 待确认问题

无。用户已确认取消导航下拉与其中的联系入口、`/partners` 直接展示供应商生态、站点仅保留中英文，并使用指定地球夜景首屏。

## Feature Spec

### 统一语言

| 术语 | 定义 | 代码命名 |
| --- | --- | --- |
| 客户与合作入口 | 直接进入供应商生态的主导航链接 | `partners` |
| 供应商生态 | 可搜索的供应商公开目录 | `supplierEcosystem` |
| 供应商 | 目录中的品牌或公司主体 | `supplier` |
| 资料已就绪 | 可进入详情并下载资料 | `ready` |
| 资料准备中 | 仅展示、不可进入详情 | `preparing` |
| 产品资料 | 与单个产品关联的 PDF | `document` |

界面、数据和代码统一使用 `supplier` 表达“供应商”，不继续用 `alliance` 表达新目录。

### 业务规则

| 规则 | 触发条件 | 约束与用户可见结果 | 验收场景 |
| --- | --- | --- | --- |
| R1 导航直接进入目录 | 用户点击“客户与合作” | 不显示二级菜单，桌面端和移动端都直接进入 `/partners` | A1 |
| R2 列表地址统一且兼容旧链接 | 用户访问 `/partners` 或旧 `/partners/suppliers` | `/partners` 直接显示目录；旧地址使用 replace 重定向到规范地址 | A2 |
| R3 搜索即时生效 | 用户输入或清空搜索词 | 忽略首尾空格和大小写，按名称、别名、产品及关键词过滤；清空恢复全部 | A3 |
| R4 无结果可恢复 | 搜索无匹配 | 显示无结果说明和清空操作，不出现空白区域 | A4 |
| R5 就绪状态控制详情入口 | 用户浏览或操作卡片 | 4 家就绪卡片为链接；7 家准备中卡片无空链接并显示状态 | A5 |
| R6 详情必须属于已知供应商 | 用户访问详情路由 | 有效且就绪的 slug 显示详情；未知或未就绪 slug 进入站点 404 | A6 |
| R7 产品资料一一对应 | 用户点击 PDF 下载 | 每个产品只展示其已配置的 PDF；不存在文件时不生成下载入口 | A7 |
| R8 中英文结构一致 | 用户切换中英文 | 页面结构、供应商数量、就绪状态和文件映射不变，只切换文案 | A8 |
| R9 站点只提供中英文 | 用户打开语言入口或带着旧语言缓存访问 | 只显示中文、English；旧 `fr`/`es` 缓存回退为中文并被覆盖 | A9 |
| R10 首屏使用指定图文 | 用户进入供应商生态 | 显示用户提供的地球夜景图、主标题与说明文字；文字保持可翻译 HTML | A10 |

### 用户流程

- 主流程：点击“客户与合作” → 进入供应商生态 → 搜索或浏览 → 打开就绪供应商 → 查看产品 → 下载 PDF。
- 替代流程：直接访问供应商生态或已知详情 URL；清空搜索查看完整目录。
- 状态流程：准备中卡片展示状态但不可进入；搜索无结果时清空关键词恢复。
- 异常流程：未知详情 slug 进入现有 404；缺少产品图片时保持文字和 PDF 可用，不展示破损链接。

### 领域模型影响

- 新增静态前端 `Supplier`、`SupplierProduct` 与 `SupplierStatus` 模型。
- 供应商拥有多个产品；产品拥有零个或多个 PDF 资料，但公开可点击产品至少有一个资料文件。
- 数据权威源为 `src/data/suppliers.ts` 与 `public/media/partners/`。
- 无数据库、API、权限、并发、事务、领域事件或数据迁移。

### 边界场景

- 空搜索、纯空格、大小写和中英文关键词。
- 搜索无结果。
- 准备中供应商不可点击、不可通过键盘误进入。
- 未知或准备中 slug。
- 产品只有 PDF、没有独立图片。
- 中文、英文及旧法西文缓存回退中文。
- 桌面、平板、手机和 `prefers-reduced-motion`。
- PDF 文件名包含空格、括号或非 ASCII 字符时仍可正常访问。

### Acceptance Scenarios

- **A1** Given 用户在桌面或移动导航中找到“客户与合作”，When 点击该链接，Then 直接进入 `/partners`，且页面中不存在导航展开按钮和二级菜单。
- **A2** Given 用户访问 `/partners`，When 路由渲染，Then 直接显示供应商生态；Given 用户访问旧 `/partners/suppliers`，Then 地址以 replace 方式归一到 `/partners`。
- **A3** Given 供应商目录已显示 11 家，When 输入供应商或产品关键词，Then 卡片即时缩减为匹配集合；清空后恢复 11 家。
- **A4** Given 搜索词没有匹配，When 结果更新，Then 页面显示无结果说明和清空搜索操作。
- **A5** Given 4 家资料已就绪、7 家资料准备中，When 用户浏览卡片，Then 只有 4 家具有可聚焦详情链接，其他卡片显示准备中状态。
- **A6** Given 用户访问有效就绪 slug，When 页面渲染，Then 显示对应供应商和产品；Given slug 无效或供应商未就绪，Then 显示 404。
- **A7** Given 某产品配置了 PDF，When 用户点击下载，Then 链接指向该产品的真实文件并使用下载语义。
- **A8** Given 用户切换中英文，When 页面更新，Then结构、状态与资料映射保持一致。
- **A9** Given 语言入口已渲染，Then 只存在中文和 English；Given 本地仍保存 `fr` 或 `es`，When 应用启动，Then 使用中文并覆盖旧值。
- **A10** Given 用户进入 `/partners`，When 首屏渲染，Then 显示地球夜景图、“链接世界，航向未来”和“每一处航迹，都有我们的伙伴。”；切换英文后显示对应英文文案。

### 非目标确认

本次不实现视频、交易、供应商管理、远程搜索、下载统计、内容翻译服务或后台。

## Design Plan

### 变更目标与影响域

供应商生态成为 `/partners` 的规范内容，全站导航的 partners 项简化为直接链接；旧 `/partners/suppliers` 仅作兼容跳转。联系页、供应商详情、产品目录、新闻和其他合作子路由不改变。

### 放置位置与依赖方向

- 静态领域数据：`src/data/suppliers.ts`。
- 页面接口层：`src/pages/SupplierEcosystemPage.tsx`、`src/pages/SupplierDetailPage.tsx`。
- 导航编排：`src/layouts/SiteLayout.tsx`。
- 中英文文案：`src/i18n/supplierMessages.ts`，由页面按 `contentLocale` 读取。
- 专属样式：`src/styles/supplier-ecosystem.css`，由页面模块加载。
- 媒体：`public/media/partners/`。

依赖保持 `页面 / 导航 → i18n / 供应商数据 → 静态媒体路径`；数据与文案不依赖 React 或页面。

### 模型边界

静态数据模型只包含稳定标识、状态、媒体与文件路径；可翻译名称、简介、产品说明和搜索关键词位于供应商 i18n 域。页面通过 supplier key 组合两者，不使用松散字典。

### 视觉方向

- 模式：公开目录，兼顾“Persuade”首屏识别与“Operate”检索效率。
- 色彩：继承现有任务黑、Navlyn 蓝、系统白和仪表灰；不引入第二套品牌色。
- 首屏：用户提供的地球夜景图作为上半段视觉，标题与说明文字在独立深色区域中居中呈现；搜索框紧接首屏，成为从叙事到操作的交接点。
- 目录：四列卡片使用真实 Logo、固定媒体框和明确状态，不使用装饰性图标卡或虚构数据。
- 记忆点：地球夜景中的城市灯光与“链接世界”文案共同表达供应链网络。
- 动效：只在可交互卡片上使用轻微方向性抬升；减少动态效果时关闭。

### 替代方案

- 放弃继续保留导航下拉：用户已将“客户与合作”明确为供应商生态的直接入口，下拉只会增加一次选择。
- 放弃为 7 家缺资料供应商创建空详情页：违反“状态明确”和不制造死路的原则。
- 放弃将视频加入详情：用户已明确严格按 Word，只展示图片与 PDF。
- 放弃把翻译字段并入结构数据：会让法西文回退和后续内容维护变得含糊。

### 验证方式

数据单测验证 11/4/7 数量、slug 唯一、文件归属和搜索索引；组件测试验证直接导航、双语入口、真实输入过滤、空状态、就绪状态、详情及下载；生产构建验证路由和类型。桌面、移动端通过浏览器实际检查。
