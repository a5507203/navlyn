# ARC GCS 产品页

## Concept Brief

### 当前阶段判断

现有 `/arc-os` 页面从 ARC ENGINE 静态介绍页升级为 ARC GCS 产品展示与资源入口，属于用户可感知的页面重构。

### 目标用户

- 无人机测绘、巡检与多机协同作业人员：需要快速理解 ARC GCS 的核心能力。
- 潜在客户与交付人员：需要确认平台适配范围并找到软件下载、使用手册和售后入口。

### 核心问题

旧页面的静态图片与 ARC ENGINE 文案无法呈现 ARC GCS 的真实操作能力，也没有软件下载、使用手册和售后支持入口。

### 核心概念定义

- **ARC GCS 产品页**：ARC GCS 的公开产品介绍与资源入口；不是在线地面站，也不承载账号或任务数据。
- **能力演示视频**：展示语音助手、一键绘区、多形态混排、风险预检的真实操作素材；由 Navlyn 提供，页面只负责播放。
- **下载入口**：指向外部 ARC GCS 安装包或手册 URL；URL 未配置时保留可见但不可操作的入口。
- **售后入口**：通过 `mailto:support@navlyn.com` 打开用户的邮件客户端。

### MVP 边界

1. 保留 `/arc-os` 路由和全站导航结构。
2. Hero 使用 `arc首图`，包含 ARC GCS 下载入口。
3. 按需求顺序展示四个大标题及对应视频。
4. 页面末尾提供第二个 ARC GCS 下载入口、ARC GCS 使用手册入口和售后邮箱。
5. 首页轮播中的 `arc-gcs.jpg` 单独替换为用户提供的 `ARC适配banner.jpg`，不把该图放进 ARC GCS 页面。
6. 支持现有中、英、法、西四种语言、桌面端和移动端。
7. 视频使用浏览器兼容的 H.264/AAC，图片使用网页优化衍生文件。

### 非目标

- 不开发安装包托管、账号、在线升级、埋点或下载统计服务。
- 不修改 ARC GCS 视频内容、软件界面或品牌图形。
- 不新增路由，不改变导航或其他产品页结构；首页仅替换对应 ARC 轮播图并优化加载策略。

### 关键假设

- `语音交互.mp4` 对应“AI 语音助手｜极简操控，高效作业”。验证依据：素材目录命名和唯一对应关系。
- 四个视频由用户主动播放，使用原生控制器及 `preload="none"`，首屏不请求视频文件内容。
- Hero 和页面末尾资源区的两个软件下载入口共用 `VITE_ARC_GCS_DOWNLOAD_URL`。
- 使用手册入口使用独立的 `VITE_ARC_GCS_MANUAL_URL`。
- URL 为空时入口设置为禁用，并展示“下载地址即将开放”；不使用 `#` 或空链接。

### 待确认问题

无。软件下载与手册 URL 按产品方决定暂时留空，后续通过环境配置补入。

## Feature Spec

### 统一语言

| 术语 | 定义 | 代码命名 |
| --- | --- | --- |
| ARC GCS | 低空 AI 操作系统与地面控制软件 | `arcGcs` |
| 产品下载 | ARC GCS 安装包的外部下载地址 | `downloadUrl` |
| 使用手册 | ARC GCS 使用手册的外部下载地址 | `manualUrl` |
| 售后支持 | ARC GCS 售后邮件入口 | `supportEmail` |

页面、代码和 SEO 统一使用“ARC GCS”，不继续使用“ARC ENGINE”作为本页产品名。

### 业务规则

| 规则 | 触发条件 | 约束与用户可见结果 | 验收场景 |
| --- | --- | --- | --- |
| R1 素材顺序固定 | 用户浏览页面 | Hero 后依次为语音、一键绘区、多形态混排、风险预检、资源支持 | A1 |
| R2 下载地址必须有效 | 下载 URL 已配置 | 入口为可聚焦链接，并在新标签页打开真实 URL | A2 |
| R3 未配置地址不跳转 | 下载 URL 为空或无效 | 入口可见、禁用，并显示待开放提示 | A3 |
| R4 视频兼容网页播放 | 用户点击视频播放 | 使用 H.264/AAC MP4、原生控制器、内联播放 | A4 |
| R5 售后邮箱固定 | 用户点击售后邮箱 | 打开 `mailto:support@navlyn.com` | A5 |
| R6 多语言结构一致 | 用户切换语言 | 页面结构不变，交互标签使用对应语言 | A6 |
| R7 首页 ARC 轮播图来源固定 | 用户浏览首页 | 第一张 ARC 轮播图使用 `ARC适配banner.jpg` 的网页优化衍生文件，其他轮播内容不变 | A7 |

### 用户流程

- 主流程：进入 `/arc-os` → 识别 ARC GCS → 浏览四项能力 → 查看下载与售后资源。
- 替代流程：用户直接从 Hero 或页面末尾资源区进入同一个软件下载地址。
- 异常/恢复流程：URL 未配置时入口不跳转并说明待开放；媒体加载失败时标题和资源入口仍可浏览。

### 领域模型影响

本功能仅涉及前端静态内容、媒体和构建时环境配置。无数据库、API、领域事件、权限或持久化模型变更。

### 边界场景

- 空 URL：禁用而不是跳转当前页面。
- 非 HTTP(S) URL：视为未配置并输出明确的配置错误日志。
- 小屏设备：视频保持 16:9，媒体完整显示；标题允许自然换行。
- 减少动态效果：页面不依赖自动播放或滚动动画完成核心任务。
- 重复点击：普通外部链接，无本地状态和重复提交问题。

### Acceptance Scenarios

- **A1** Given 用户进入 `/arc-os`，When 页面渲染，Then Hero、四项能力和资源区按规格顺序出现，页面中没有额外的适配 Banner 段落。
- **A2** Given 合法软件下载 URL，When 用户点击任一软件下载入口，Then 两个入口均指向同一 URL。
- **A3** Given 下载 URL 留空，When 页面渲染，Then三个下载入口可见但不可点击，并显示待开放状态。
- **A4** Given 浏览器支持 H.264，When 用户播放任一能力视频，Then 视频以内联原生控制器播放且不会预加载完整文件。
- **A5** Given 用户需要售后支持，When 点击邮箱，Then链接目标为 `mailto:support@navlyn.com`。
- **A6** Given 用户切换现有任一语言，When ARC GCS 页面重新渲染，Then所有必需字段存在且页面结构保持一致。
- **A7** Given 用户进入首页，When 轮播首图渲染，Then 使用 `ARC适配banner.jpg` 的优化衍生文件，后续轮播图仍按原顺序渐进加载。

### 非目标确认

不实现软件下载后端、下载统计、表单、登录、版本检测或自动更新。

## Design Plan

### 变更目标与影响域

重构 ARC GCS 页面接口层，新增 ARC GCS 静态媒体与构建时下载配置；同时将首页指定 ARC 轮播图替换为用户素材并优化媒体加载。路由、全站布局、联系表单、产品目录和其他页面结构不受影响。

### 放置位置与依赖方向

- 页面编排：`src/pages/ArcPage.tsx`。
- ARC 专属样式：`src/styles/arc-gcs.css`，由 `ArcPage` 路由组件按需加载。
- 下载配置：`src/config/arcGcs.ts`，只读取 Vite 环境变量并向页面提供经过校验的 URL。
- 文案：现有 `src/i18n/messages*.ts` 的 `arc` 域。
- 媒体：按用途归档至 `public/media/arc-gcs/`、`public/media/home/`、`public/media/products/`、`public/media/brand/` 等目录。

依赖保持 `页面 → 配置 / i18n / 静态媒体路径`，配置层不依赖页面。

### 视觉方案

- 色彩：`#02050B` 任务黑、`#0D55C8` Navlyn 蓝、`#493CFF` 电光紫、`#26E58A` 航线绿、`#F5F7FF` 系统白、`#8491A6` 仪表灰。
- 字体：沿用站点中文和正文字体；英文能力标签使用紧凑的系统窄体回退和加宽字距，避免引入外部字体依赖。
- 布局：Hero 全宽主导；四项能力使用“大标题 → 16:9 操作视窗”的连续任务流；资源区使用三列信息布局，窄屏下依次堆叠。
- 识别元素：一条来自航线规划界面的绿色“任务航线”贯穿能力段落，是唯一强调性装饰。
- 克制项：不加入无业务含义的统计卡、编号时间线或多余滚动动画。

### 替代方案

- 放弃直接复用旧版四张静态功能图：无法满足真实视频展示需求。
- 放弃四视频静音自动播放：素材总时长和体积较大，会造成不必要流量、性能与无障碍问题。
- 放弃空 `href`/`#` 占位：会误导用户并导致页面跳顶。

### 验证方式

组件测试覆盖结构、媒体属性、空 URL、邮箱与多语言；生产构建验证静态资源打包。最终桌面、移动布局及视频播放由用户验收。

## 不变量台账

| 不变量 | 权威数据源 | 锁/事务 | API 投影 | 前端状态 | 回归验证 |
| --- | --- | --- | --- | --- | --- |
| 两个软件下载入口使用同一地址 | `VITE_ARC_GCS_DOWNLOAD_URL` | 不适用：静态前端 | 不适用：无 API | 构建时只读配置，无本地状态 | `ArcPage.test.tsx` 下载入口场景 |
| 空或非法 URL 不产生可点击链接 | `src/config/arcGcs.ts` 校验结果 | 不适用 | 不适用 | 页面按 `undefined` 渲染禁用态 | 配置单测 + 页面空值场景 |
| 四项能力及顺序固定 | `page.arc.features` 与页面媒体映射 | 不适用 | 不适用 | 无异步状态 | 页面结构测试 |
| 售后邮箱固定为 support@navlyn.com | ARC 配置常量 | 不适用 | 不适用 | 无本地状态 | 页面邮箱断言 |

## Test Plan

| 场景来源 | 风险类型 | 层级 | 覆盖方式 |
| --- | --- | --- | --- |
| A1、R1 | Happy path | 组件测试 | 使用真实页面与 i18n Provider，断言 Hero、四个视频、资源区及顺序 |
| A2、R2 | Happy path | 配置单测 | 注入合法 HTTP(S) 字符串，断言标准化 URL |
| A3、R3 | Empty / boundary | 配置 + 组件测试 | 空值和非法协议返回未配置；页面没有对应 `href` 且显示禁用状态 |
| A4、R4 | Compatibility | 组件测试 + 用户验收 | 断言四个 `video` 的 `controls`、`playsInline`、`preload=none`；用户实际播放 H.264 文件 |
| A5、R5 | Happy path | 组件测试 | 断言 `mailto:support@navlyn.com` |
| A6、R6 | Data integrity | 现有 i18n 测试 | 四语结构一致；构建通过 TypeScript 校验 |
| A7、R7 | Performance / regression | 首页组件测试 | 断言首图路径、初次只挂载第一张图，切换后才挂载已访问图片 |
| 响应式视觉 | Boundary | 用户验收 | 桌面与移动端检查不横向溢出、不裁切关键软件界面 |

权限、并发、数据库一致性和后端失败不适用：本功能没有认证、提交、持久化或外部请求。
