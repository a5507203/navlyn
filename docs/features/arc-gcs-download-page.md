# ARC GCS 下载页

## Concept Brief

### 当前阶段判断

已完成概念探索与需求确认，进入实现和交付验证阶段。路由、平台范围、初始禁用状态、FAQ 顺序、版本与语言范围均已由产品方确认。

### 目标用户

- 准备安装 ARC GCS 的 Windows 与 Android 用户。
- 需要确认基础配置、安装方式、离线能力与设备适配范围的作业人员。

### 核心问题

现有 ARC GCS 产品页只有暂不可用的下载按钮，无法承载多平台安装包、版本信息和安装前常见问题。用户需要一个独立、清晰且可持续补充安装包的下载入口。

### 核心概念

- **下载页**：`/downloads/arc-gcs` 下的 ARC GCS 安装资源与 FAQ 页面；不是通用下载中心。
- **平台下载项**：Windows、Android 两个彼此独立的安装入口。
- **可用状态**：仅当对应构建环境变量包含合法的绝对 HTTP(S) URL 时启用；否则保持可见且禁用。

### MVP

1. 新增 `/downloads/arc-gcs` 路由，并继续归属顶部 ARC GCS 导航。
2. 使用产品方提供的 `首图banner.png` 生成响应式 WebP 首图。
3. 展示版本 `v1.0.0` 和 Windows、Android 两个平台入口。
4. 首次发布时两个入口均禁用并明确显示“即将开放”。
5. 将 ARC GCS 产品页的 Hero 与客户端卡片改为站内跳转到新下载页；手册入口保持原逻辑。
6. 中英文展示 Q1–Q9，答案默认可见；原 Q9、Q10 顺延为 Q8、Q9。
7. 桌面端 FAQ 两列、移动端单列，保留现有 SiteLayout、Footer 与联系入口。

### 非目标

- 不新增顶部“下载”导航项。
- 不提交安装包，不实现下载后端、统计、登录、许可管理、自动更新或系统自动检测。
- 不提供或预留 macOS 下载入口。
- 不改动 ARC GCS 产品能力内容、视频与手册下载逻辑。

### 关键假设

- 安装包后续由产品方提供，并通过构建环境变量接入外部 HTTPS 下载地址。
- FAQ 中 Windows 与 Android 的要求来自产品方文档。
- Banner 内文字属于视觉素材，页面仍提供真实 DOM 标题、版本与平台状态，以满足移动端可读性和无障碍需求。

### 待确认问题

无阻塞项。两个安装包 URL 属于后续发布输入，不影响当前下载页以禁用状态上线。

## Feature Spec

### Concept Brief 来源

以上 Concept Brief 由产品方提供的 `下载页面.docx`、首图素材和本次对话确认共同形成，是本 Feature Spec 的唯一需求输入。

### 统一语言

| 术语 | 定义 | 代码命名 | 不使用 |
| --- | --- | --- | --- |
| ARC GCS 下载页 | ARC GCS 多平台安装资源与 FAQ 的独立页面 | `ArcGcsDownloadPage` | 通用下载中心 |
| 平台下载项 | Windows、Android 中某一个独立发布入口 | `ArcGcsDownloadPlatform` | 一个通用下载地址 |
| 已开放 | 对应平台配置了合法绝对 HTTP(S) URL | `is-available` | 仅用颜色表达 |
| 即将开放 | 对应平台 URL 缺失或非法，入口可见但禁用 | `pendingStatus` | 空链接、`#` |
| 当前版本 | 页面统一展示的产品版本 `v1.0.0` | `ARC_GCS_DOWNLOAD_VERSION` | 从 Banner 图片解析版本 |

### 业务规则

| 规则 | 触发条件 | 约束与用户可见结果 |
| --- | --- | --- |
| R1 路由唯一 | 用户进入下载页 | 使用规范路径 `/downloads/arc-gcs` |
| R2 软件入口统一 | 用户点击 ARC GCS 产品页任一软件下载入口 | 站内跳转到 `/downloads/arc-gcs` |
| R3 平台顺序固定 | 下载页渲染 | Windows → Android |
| R4 平台状态独立 | 任一平台 URL 配置变化 | 只影响对应平台，不改变另一个平台 |
| R5 URL 安全 | URL 缺失、空白或非 HTTP(S) | 显示禁用按钮，不生成空链接或 `#` |
| R6 版本唯一 | 下载页渲染 | 所有可见版本信息来自常量 `v1.0.0` |
| R7 FAQ 连续 | FAQ 渲染 | 共 9 项，编号 Q1–Q9，答案无需点击即可阅读 |
| R8 双语一致 | 用户切换中英文 | 结构、平台顺序与 FAQ 数量不变 |
| R9 导航归属 | 用户位于下载页 | 桌面与移动导航均将 ARC GCS 标记为当前栏目 |

### 平台配置

| 平台 | 环境变量 | 初始状态 |
| --- | --- | --- |
| Windows | `VITE_ARC_GCS_WINDOWS_DOWNLOAD_URL` | 禁用 |
| Android | `VITE_ARC_GCS_ANDROID_DOWNLOAD_URL` | 禁用 |

环境变量只接受绝对 HTTP(S) URL。旧的 `VITE_ARC_GCS_DOWNLOAD_URL` 不再控制 ARC GCS 产品页软件入口，也不作为 Windows 的隐式兜底；部署环境可在确认不再使用后清理该变量。

### 用户流程

- 主流程：ARC GCS 产品页 → 点击“下载 ARC GCS” → 下载页 → 查看版本与平台状态 → 阅读 FAQ。
- 直接流程：访问 `/downloads/arc-gcs` → 查看平台与 FAQ。
- 未来启用流程：部署方配置某个平台 URL 并重新构建 → 该平台按钮成为外部下载链接。
- 异常流程：URL 缺失或非法 → 对应入口保持禁用，其他平台不受影响。

### 领域模型影响

本功能只有静态前端页面、构建时环境配置和媒体文件，不新增后端实体、数据库、API、权限、领域事件或持久化状态。平台 URL 是两个相互独立的构建配置值，不形成需要事务一致性的聚合。

### 边界场景

- 空白、缺失、相对路径或非 HTTP(S) URL：对应平台保持禁用并输出不包含敏感值的配置错误。
- 单平台已配置：只启用该平台，另一个保持禁用。
- 重复点击：外部普通链接，无本地提交状态；禁用按钮不会触发动作。
- 权限、并发、时区与过期：当前无账户、写入、计时或后端状态，不适用。
- 外部下载失败：由安装包托管端返回；当前页不伪造成功状态，用户可返回页面或联系支持。
- 小屏幕：Banner 作为装饰图，真实 DOM 标题、版本和状态继续可读；平台按钮自适应排列，FAQ 依次单列。
- 内容语言：仅站点当前可切换的中文、英文；法语和西班牙语归档内容不成为下载页入口。

### Acceptance Scenarios

- **A1** Given 用户点击 ARC GCS 产品页任一软件入口，When 路由变化，Then 到达 `/downloads/arc-gcs`。
- **A2** Given 两个平台 URL 均未配置，When 下载页渲染，Then 两个按钮均可见、禁用且没有平台下载链接。
- **A3** Given 仅一个平台配置合法 URL，When 下载页渲染，Then 仅该平台为可点击外链。
- **A4** Given 用户切换中文或英文，When 页面更新，Then 版本、两平台、九条 FAQ 和页面结构保持完整。
- **A5** Given 用户查看 FAQ，When 页面初次渲染，Then Q1–Q9 的问题与答案均已在 DOM 中且无需展开。
- **A6** Given 用户访问 `/downloads/arc-gcs`，When 查看顶部导航，Then ARC GCS 显示激活并具有当前栏目语义。
- **A7** Given 窄屏设备，When 页面渲染，Then 平台按钮移入 Banner 下方并自适应排列，FAQ 为单列且页面无横向溢出。

## Design Plan

- 页面组件：`src/pages/ArcGcsDownloadPage.tsx`。
- 专属文案：`src/i18n/arcGcsDownloadMessages.ts`，仅覆盖站点当前可切换的中文和英文。
- 平台配置：`src/config/arcGcs.ts`，集中校验两个独立 URL。
- 专属样式：`src/styles/arc-gcs-download.css`，延续 ARC GCS 的任务黑、品牌蓝、电光紫和系统白。
- 媒体：`public/media/arc-gcs/download/`，只提交从 8000×4500 PNG 生成的网页优化衍生图。
- 首图使用 `<picture>` 与 1280/1920/2560 宽度集，明确尺寸并优先加载；桌面端两个横向描边下载按钮位于 Banner 的下载区，移动端按钮进入正常文档流。
- FAQ 使用单一顺序数组与 CSS Grid，桌面两列、移动端一列，不使用折叠面板。
